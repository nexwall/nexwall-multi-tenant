# nexwall-controller Helm chart

One `helm install` = one fully isolated tenant. Translates 1:1 from the `podman run` commands already validated in `nexwall-controller`'s `dev-nexwall.sh` (single-VM dev harness) to k8s resources.

## Mapping from dev-nexwall.sh

| dev-nexwall.sh (podman) | This chart |
|---|---|
| `podman pod create` | Namespace (created by the Management Plane before `helm install`, not by this chart) |
| `podman run ... vpn` (`--privileged --cap-add=NET_ADMIN --device /dev/net/tun`) | `templates/vpn-deployment.yaml` |
| `podman run ... db` (`-v ovpn-data`) | `templates/db-statefulset.yaml` |
| `api.env` heredoc | `templates/secrets.yaml` |
| `podman run ... api/ui/proxy` | `templates/api-deployment.yaml`, `ui-deployment.yaml`, `proxy-deployment.yaml` |
| `start_monitoring()` (loki/promtail/prometheus/grafana) | `templates/monitoring/*.yaml` |
| Traefik route files dropped via `podman exec -i proxy` | still generated by the proxy container itself at startup — unchanged in k8s, this chart only routes the Ingress to the proxy Service |

## Known TODOs before Phase 1's first real deploy

1. **Proxy env vars** (`proxy-deployment.yaml`) — inferred, not yet verified against `nexwall-controller/proxy/entrypoint.sh` line by line.
2. **Grafana dashboards JSON** — the two dashboards matching the UI's hardcoded links (`W3S__804z`, `liz0yRCZz`) exist as files in the single-VM dev setup but aren't yet a ConfigMap in this chart.
3. **VPN → cluster-Service routing for promtail** — needs to be proven that traffic from a connected firewall (VPN tunnel CIDR) can reach the `promtail` Service's ClusterIP through the `vpn` pod's netns. Worked trivially under Podman host networking; not yet proven under a CNI pod network. See the TODO comment in `templates/secrets.yaml`.
4. **`secrets.yaml` defaults are placeholders** (`CHANGE_ME`) — real deploys must override via `--set-file` or an external-secrets source, never commit real values to a `values-<tenant>.yaml` in git.

## Install

```
helm install tenant-7-acme . -f values-acme.yaml -n tenant-7-acme --create-namespace
```

`values-acme.yaml` must satisfy `values.schema.json` — at minimum `tenantId`, `slug`, `vpnCidr`, `vpnPort`, `subdomain` (see `docs/adr/0004-network-allocation.md` in the repo root for how those are assigned).
